# 修复视频切分时多音轨丢失问题 - 设计文档

**日期**: 2026-07-07  
**状态**: 已批准  
**问题**: 当前视频切分功能只映射第一条音轨，导致多音轨专业视频（如 8 条单声道音轨）切分后在所有平台上都听不到声音

---

## 1. 问题背景

### 1.1 现象描述

用户使用专业摄像设备（如 Sony）录制的视频文件包含 8 条独立的单声道音频流（PCM 编码），原始视频在 Mac 上可以正常播放，但经过 MotionSlice 切分后，在 Mac 上也听不到声音。

### 1.2 根本原因

当前代码 `export-handler.ts:212` 使用以下 FFmpeg 参数：

```typescript
.outputOptions(['-map', '0:v:0', '-map', '0:a:0?']);
```

这行代码只映射：
- `0:v:0` - 第一条视频流
- `0:a:0?` - 第一条音频流（`?` 表示可选）

对于包含 8 条音频流（索引 1-8）的源视频，这个命令只会复制第一条音频流。如果第一条音轨是空的或备用轨道，导出后的视频就没有声音。

### 1.3 用户需求

> "切分视频不应该处理音轨，原来是几条就是几条，切分后只是把视频片段切分了，不应该影响其他内容。"

核心诉求：
- 保留所有原始音频轨道的数量和结构
- 切分是时间维度的裁剪，不涉及流的选择和过滤
- 压缩主要针对视频质量，音频不会显著影响文件大小

---

## 2. 技术方案

### 2.1 方案选型

经过三种方案对比（映射所有流 / 映射所有音视频流 / 智能检测音轨），最终采用 **方案 B（映射所有视频和音频流）**：

```typescript
.outputOptions(['-map', '0:v', '-map', '0:a']);
```

**选择理由：**
1. **保留所有音视频流**：8 条单声道音轨全部保留
2. **过滤异常数据流**：专业设备录制的视频常包含 timecode、metadata 等数据流，直接使用 `-map 0` 映射所有流时，MP4 容器会因不支持这些流而报错（`Could not find tag for codec...`）
3. **鲁棒性最优**：在保留音视频完整性的同时，避免批量导出时因特殊数据流导致的崩溃

**不选择其他方案的原因：**
- **方案 A（`-map 0`）**：虽然最简单，但会将 timecode/subtitle/data tracks 一并映射，在 MP4 容器下会报错
- **方案 C（智能检测）**：需要额外 ffprobe 调用，增加复杂度和性能开销，收益不明显

### 2.2 核心修改

**文件：** `src/main/handlers/export-handler.ts`  
**位置：** 第 212 行（`exportSegment` 函数）

```typescript
// 修改前
.outputOptions(['-map', '0:v:0', '-map', '0:a:0?']);

// 修改后
.outputOptions(['-map', '0:v', '-map', '0:a']);
```

**效果说明：**
- `-map 0:v`：映射所有视频流（通常只有一条，但支持多视频流）
- `-map 0:a`：映射所有音频流（8 条单声道音轨全部保留）
- 自动过滤掉不兼容的数据流（timecode、subtitle、data tracks）

## 3. 编码参数适配

### 3.1 无需调整现有逻辑

现有的编码参数配置无需修改，因为 FFmpeg 的 `-c:v` 和 `-c:a` 参数会自动应用到所有对应类型的流。

### 3.2 无损导出（quality = 100）

```typescript
if (format === 'mp4') {
  command.outputOptions([
    '-c:v', 'copy',           // 所有视频流直接拷贝
    '-c:a', 'aac',            // 所有音频流转 AAC（8 条统一处理）
    '-b:a', '192k',           // 每条音轨码率 192k
    '-movflags', '+faststart',
  ]);
} else {
  command.outputOptions(['-c', 'copy']);  // MOV/AVI 格式所有流直接拷贝
}
```

**处理逻辑：**
- MP4 容器：视频流拷贝，音频流统一转为 AAC 编码（兼容性）
- MOV/AVI 容器：所有流直接拷贝（保留 PCM 原始编码）

### 3.3 压缩导出（quality < 100）

```typescript
const crf = Math.round(28 - (quality / 100) * 10);
command.outputOptions([
  '-c:v', 'libx264',        // 视频重编码
  '-crf', String(crf),      // 质量参数（18-28）
  '-preset', 'fast',
  '-c:a', 'aac',            // 所有音频流转 AAC（8 条统一处理）
  '-b:a', '128k',           // 每条音轨码率 128k
]);
if (format === 'mp4') {
  command.outputOptions(['-movflags', '+faststart']);
}
```

**处理逻辑：**
- 视频流：重新编码为 H.264，通过 CRF 控制质量
- 音频流：统一转为 AAC 编码，所有音轨使用相同码率
- 压缩主要针对视频，音频不做额外压缩

## 4. 影响范围分析

### 4.1 代码修改

- **修改文件数量**：1 个文件
- **修改行数**：1 行代码
- **风险等级**：低（仅修改 FFmpeg 参数，不涉及业务逻辑）

### 4.2 兼容性验证

**修改前：**
- ✅ 单音轨视频：正常（第一条音轨被映射）
- ❌ 多音轨视频：异常（只保留第一条音轨，其他丢失）

**修改后：**
- ✅ 单音轨视频：正常（映射唯一的音轨）
- ✅ 多音轨视频：正常（映射所有音轨）
- ✅ 包含数据流的专业视频：正常（数据流被过滤，不会报错）

### 4.3 性能影响

**导出时间：**
- 无损导出：无影响（视频流拷贝，音频流转码时间略增，但音频处理速度远快于视频）
- 压缩导出：无影响（瓶颈在视频重编码，音频转码耗时可忽略）

**文件体积：**
- 单音轨视频：无变化
- 多音轨视频：
  - 8 条 PCM 音轨 → 8 条 AAC 音轨（192k），体积显著减少
  - 8 条 AAC 音轨总码率 = 192k × 8 = 1.5 Mbps，占比小于视频码率（通常 10+ Mbps）
